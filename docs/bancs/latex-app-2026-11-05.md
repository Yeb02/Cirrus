# Banc LaTeX dans l'app — 2026-11-05

**Verdict : RÉUSSI** (p95 de l'aperçu ≤ 300 ms après la pause de frappe, pour le résumé et pour le `.tex`)

- Moteur : pdfTeX 3.141592653-2.6-1.40.29 (TeX Live 2026), la TinyTeX du banc (`CIRRUS_TINYTEX=bench/latex/vendor/TinyTeX`), `DEFAULT_PREAMBLE`, `latexWarmProcesses` 2. Processeur AMD Ryzen 7 7435HS, sur secteur, mode « Équilibré ».
- App : l'app construite (`electron-vite build`, après la tâche 7), une fenêtre de 1600×1000, la vue `0,140,1`, sur une copie neuve de la base de test à chaque session, un profil à part. Jamais la base de l'utilisateur.
- Pilote : le protocole des outils de Chrome (`--remote-debugging-port`), avec de vraies entrées (`Input.dispatchMouseEvent`, `Input.insertText`). Rien de l'app n'est modifié pour mesurer :
  - **fin de la pause** : la minuterie de `latexTypingPauseMs` (300 ms) du planificateur, au moment où elle se déclenche (`window.setTimeout` enveloppé depuis le pilote) ;
  - **image dessinée** : le canevas de la première page du nouveau PDF, mis dans la page une fois dessiné (un `MutationObserver`), et l'image suivante (`requestAnimationFrame`) ;
  - **où va le temps** : l'IPC `cirrus:latex:compile` chronométrée dans le principal (son gestionnaire enveloppé avant le chargement de l'app), et la lecture du PDF (`cirrus-file://latex/…`) vue par le protocole.
  - Toutes les horloges sont `performance.timeOrigin + performance.now()`, ou l'heure murale du protocole : à la milliseconde près d'un processus à l'autre.
- Modifications : une frappe (« ␣a », « ␣b »…) à la fin du résumé de l'entropie, dans son éditeur compact, ou à la fin de `complexité.tex`, dans son plein écran ; puis 1,2 s de repos, pour que la réserve se refasse (comme à la tâche 3). Une première frappe, non comptée, précède les 20. Trois sessions de 20, soit 60 par cas.
- p50 et p95 : au rang le plus proche (le p95 de 60 valeurs est la 57e).

Si la marge venait à manquer, le levier suivant serait pdfLaTeX lui-même, puis le dessin de pdf.js, chacun à mesurer. `mylatexformat` n'y changerait rien : le préambule est déjà chargé d'avance.

- la page est dessinée 100 ms après.

Le levier suivant serait de charger pdf.js et son travailleur d'avance, au repos, après le démarrage.
